HOW WE ESTIMATE / read the assumptions
Naive bits = code-point length × log₂(character pool). Pools: lowercase 26, uppercase 26, digits 10, ASCII symbols 33, other Unicode ≈100. Our pattern engine finds a cheap cover of dictionary words, names, substitutions, keyboard walks, sequences, repetitions, years and dates using dynamic programming. It caps the result at brute force. This is an educational heuristic inspired by pattern-based estimators, not zxcvbn or a guarantee.
Average time = guesses ÷ (2 × guesses per second); worst case = guesses ÷ speed. Log-space arithmetic keeps long passwords finite. One high-end consumer GPU: MD5 1.5×10¹¹/s; NTLM 2.5×10¹¹/s; SHA-1 4.9×10¹⁰/s; SHA-256 2.1×10¹⁰/s; bcrypt cost 12 ≈1,400/s. Rounded estimates informed by public RTX 4090 hashcat benchmarks, not a benchmark run here. Argon2id ≈100/s is an assumption: memory, iterations and parallelism change the answer dramatically.
Online rate limits: 100 guesses/hour, or an assumed unprotected 1,000/s. Hardware multiplies offline speeds only. Attackers’ word lists, password reuse, hash settings and real systems can change everything. Salts stop shared precomputation; they don’t make fast hashes slow. SAFE is a model verdict, not a security promise. Scientific values are available on time tooltips.
Passphrase generation uses the embedded word-list size. Familiar public phrases are predictable. Emoji counts use code points, not visible grapheme clusters. The score is a teaching aid, not a standard.

[LEARN] Five things worth knowing before your next password →
01 / Entropy
Bits describe a search space. Each extra bit doubles the work. That only holds if choices are unpredictable: a famous phrase is not random.
02 / Online vs offline
A website can slow login attempts. A stolen hash database lets an attacker guess on their own hardware, with no website to stop them.
03 / Length wins
More randomly chosen characters or words multiply the possibilities. Changing “a” to “@” is already in an attacker’s playbook.
04 / Hash speed
Fast hashes are great for files, poor for passwords. Slow, tuned password hashes like Argon2id make each guess expensive.
05 / Unique + 2FA
One breach should not unlock every account. A manager makes unique secrets practical. 2FA or passkeys add protection beyond a password.
